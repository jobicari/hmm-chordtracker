# V14: an N (no chord) class in the sevenths network

**Answer: no, a null result.** V14 gives V8's causal network (vocabulary A, 60 chord classes) a 61st
class, N, trained on the N labels of RWC-P and ChoCo, and a variant that also feeds the GRU the frame's
input level in dBFS. The network finds most of the reference N on validation (RWC-P 88 to 90 of 107 s,
ChoCo 165 to 170 of 219 s at lag 8, against 75 and 113 s for V10's level gate on V11), but it also calls
N on chords, 29 to 53 s of them on GuitarSet, which has no N at all. At lag 8 (1.02 s) the 3-set mean
sevenths with N scored is 72.55 to 73.07 %, below V11 seed 1 with V10's level gate (73.97 %). Holding N
back in the decoder helps every run, and the best setting found on validation reaches 73.44 % (seed 0),
still 0.53 points short. None of the three runs passes the checks set before the runs (below), so V11's
network, seed 1, stays frozen, and test is not run again: **majmin 78.1 % (network alone, 0.28 s) and
79.1 % (fixed-lag Viterbi, 0.65 s), V11's numbers, not rerun.**

| validation, lag 8 (1.02 s), mean of the 3 sets | sevenths, N scored | sevenths, N excluded | GuitarSet false N |
|---|---:|---:|---:|
| V8 seed 0 / seed 1 | 72.37 / 72.98 % | 73.65 / 74.27 % | 0 s |
| V11 seed 1 (frozen) | 73.16 % | 74.45 % | 0 s |
| V11 seed 1 + level gate 0.005 | **73.97 %** | 74.24 % | 11 s |
| N, seed 1 | 72.71 % | 72.64 % | 42 s |

## Question

Since V5 the network always names a chord: N frames are left out of training, and every second of
reference N is scored wrong (mir_eval's majmin and sevenths compare N with N). V10 added a gate after
decoding, N wherever the frame's log-CQT level is low, which on V11 gains 0.81 points of mean sevenths at
lag 8. V5.1 tried an N class on the 24-chord CNN and found it called about as many chord seconds N as it
found real N. V14 asks whether the same holds for V8's sevenths network, which now trains on ChoCo as
well, so it sees about six times more N (2,319 s against RWC-P's 379 s): can the network itself say "no chord" better than the level
gate, without losing chords? And does giving it the input level directly help?

How much N there is (`scripts/v14_census.py`, results/v14/census.md):

| set | split | N seconds | share of labelled time | first 10 s | last 10 s | mid-song |
|---|---|---:|---:|---:|---:|---:|
| RWC-P | train | 379 | 2.63 % | 15.6 % | 67.9 % | 16.5 % |
| RWC-P | validation | 107 | 2.17 % | 11.8 % | 71.6 % | 16.6 % |
| GuitarSet | train, validation | 0 | 0 % | | | |
| ChoCo | train | 1,940 | 4.02 % | 19.6 % | 37.3 % | 43.1 % |
| ChoCo | validation | 219 | 2.30 % | 19.1 % | 63.8 % | 17.0 % |

Most N is a song's ending. A perfect N class could add about 2.2 points on RWC-P and ChoCo and nothing on
GuitarSet, where any N output is a loss.

## Setup

Everything is V8's recipe (`configs/v8.yaml`: data, features, input look-ahead 2, training settings,
decoders), on the features rebuilt in V13 with the 12-bin tuning estimate, with these changes
(`configs/v14.yaml`, `scripts/run_v14.py`):

- **Targets** (`data_v8.target(..., with_n=True)`): the label N becomes class 60. X, chords outside
  vocabulary A and frames outside the annotation stay -1, left out of the loss. N has no root, so the
  pitch shift leaves it where it is (`data_v5.shift_targets` with `n_chords`, used by `data_v6` and
  `data_v7_2`'s batches; the default is unchanged). N is 3.71 % of the training frames.
- **Network** (`model_v14.ChordCRNN`): V8's CRNN with 61 outputs, built in V8's layer order, so a seed
  starts from V8's weights but for the extra class. Trained from scratch with V8's settings and seeds 1
  and 0 (`train_v14`); early stopping on the mean validation frame accuracy, now including N frames.
- **Level variant**: the GRU reads one more number per frame, the level of the 2,048 raw mono samples
  before the frame's centre, 10 log10 of the mean square (dBFS), clipped at -100 dB and divided by 100
  (`features_v14`). The GRU step of frame t gets the level of frame t + 2, the newest frame its input
  look-ahead has heard. The same function computes the cached levels and the live ones
  (`StreamingLevels`, `model_v14.StreamingCRNN`), and a test checks they are equal. Seed 1 only.
- **Prior** (`transitions_v8.training_prior` with `n_chords`): chords in all 12 keys as in V8; N is
  counted where it is, at its share of the training frames.
- **Transition matrix**: V8's Billboard matrix with an N row and column (`transitions_v8.add_n`). A chord
  goes to N at the rate counted on the training labels, 398 of 26,618 changes out of a chord (1.50 %);
  N goes to each chord by the chord's prior share.
- **Decoding**: V8's frozen points (network alone; fixed-lag Viterbi at lag 2 p_self 0.5, lag 4
  p_self 0.8, lag 8 p_self 0.98), prior power 0.25. Two decoder knobs, on the saved networks only: the
  N weight (N's evidence times x0.1 to x4, i.e. its tempered prior divided by it) and the chord-to-N
  rate (x0.5, x1, x2), 15 settings in all. The network alone is the frame argmax, which no knob changes.
- **Baselines**, on the same rebuilt validation features: V8 A seed 0 and seed 1 and V11 seed 1 (frozen),
  re-decoded, not retrained; V11 seed 1 also with `decode_v10.level_gate` at 0.005.

Three numbers per system, set and point, from the same `frame_score` tables as V10:

- **N scored**: mir_eval majmin and sevenths as they are.
- **N excluded**: reference N seconds left out. A system that never says N loses nothing here; one that
  calls N on a chord still loses those seconds.
- **N seconds**: found (reference N, output N), missed (reference N, output a chord), false (output N on
  a reference chord that majmin scores).

**Checks for going on (set before the runs).** At lag 8: the 3-set mean sevenths with N scored must beat
V11 seed 1 + gate (73.97 %, the better of its two p_self sets); the N-excluded 3-set mean sevenths must
be within 0.3 points of the V8 run with the same seed; GuitarSet must have under about 5 s of false N.
Passing all three would have allowed distilling the N network the way V11 distilled V8.

## How the evaluation avoids leakage

Same rule as every version: **test is scored, never inspected**, and V14 has no test run. The networks'
weights see train only; the transition rate and the prior are counted on train labels. Every number in
this report, the choice of epochs and the 15 decoder settings use validation (RWC-P val, GuitarSet val,
ChoCo val, never pooled across sets). The frozen system's test numbers are V11's, not rerun.

## Findings (all from validation)

**1. The N class finds N but calls too much of it, as in V5.1.** At the default decoder the network finds
82 to 84 % of the reference N on RWC-P and 75 to 78 % on ChoCo, more than the level gate (70 % and 52 %),
but it also calls N on 55 to 91 s of RWC-P chords, 97 to 119 s of ChoCo chords and 29 to 53 s of
GuitarSet, where there is no N. With N scored it gains on RWC-P over V8 with the same seed (seed 0: 72.62
vs 70.76 %) and loses on GuitarSet (69.20 vs 69.73 %).

**2. Holding N back helps every run, steadily, and boosting it always hurts.** Every step down the N
weight, from x4 to x0.1, raises sevenths with N scored, N excluded, or both. At x0.1 the false N on
GuitarSet falls to 5 to 12 s while N found on RWC-P falls only from 88 to 90 s to 75 to 81 s. The
transition rate hardly matters: halving or doubling it moves the mean by 0.04 points or less.

**3. Most of the N-excluded loss is the false N itself, not worse chords.** With the default decoder, N
seed 0 is 0.68 points below V8 seed 0 N excluded; at N weight x0.1, with false N cut to 16 / 5 / 55 s,
the gap is 0.12. What remains is ChoCo (77.83 vs 78.65 %) and, on seed 1, GuitarSet (69.43 vs 70.81 %),
where the network alone is also lower (68.11 vs 68.63 %): with one run per seed, part of this is seed
noise (V8's two seeds differ by 0.61 points at lag 8).

**4. Against its own V8 seed the N class gains on one seed only.** With N scored at lag 8 and the best
decoder setting, seed 0 gains 1.07 points over V8 seed 0 (73.44 vs 72.37 %), seed 1 loses 0.05 (72.93 vs
72.98 %). The check is against V11 + gate, which starts higher: V11's distillation adds 0.18 to 0.79
points over V8 at lag 8, and the gate another 0.81. An N network without distillation was not expected
to beat both; the check asked whether it came close enough for distillation to be worth trying. None
did: seed 0 came closest, 0.53 points short at its best setting.

**5. The input level does not help.** The level variant is below plain N on the same seed in mean
sevenths at every point (0.16 points at lag 8, 0.59 for the network alone; of the sets only GuitarSet at
lag 8 is higher, 69.28 vs 68.88 %). It calls more false N on GuitarSet (53 vs 42 s), and its kept epoch
came earlier (11 of 16). The network does not use the level to tell quiet chords from silence; the log-CQT,
relative to the song's running level, may already carry what the level adds.

## Limitations

- One training run per configuration, and the level variant on one seed only; V8's seed gap (0.61 points
  of mean sevenths at lag 8) is as large as most of the differences above.
- The 15 decoder settings and the best-setting rows are chosen on the same validation songs they are
  scored on.
- The level gate was applied to V11 only, not to the V8 seeds or to the N networks; a gate on V8 would be
  the fairer baseline for finding 4.
- About a third of RWC-P's N lies in the 2 s by which its annotations outlast the audio (V5.1, finding 5),
  so part of the reference N cannot be heard by any system; the same seconds are scored for every one.
- The training ran on the Mac's GPU from a normal terminal (see Reproduce); on the CPU an epoch takes
  about 1,900 s instead of 240 s.

## What the next version should look at

- **Keep V10's gate as the way to say N.** It is cheaper, needs no retraining, and costs chords little:
  V11 + gate is 0.21 points below V11 N excluded, while the N class is 0.12 to 1.82 below its own V8
  seed.
- **If N is tried again, train it with fewer false N in mind**: the class is over-confident on quiet chord
  passages (finding 2). Options are a smaller loss weight for N, or N from ChoCo's mid-song breaks only,
  checked on validation before any distillation.
- **The annotation tail of RWC-P** (V5.1) still bounds what any N method can gain there.

## Reproduce

Training must be launched from a normal terminal: inside a sandboxed shell PyTorch may not see the Mac's
GPU (`torch.backends.mps.is_available()` is False there) and silently trains on the CPU, about eight
times slower.

```bash
PYTHONPATH=src python scripts/v14_census.py                                  # results/v14/census.md
PYTHONPATH=src:scripts python scripts/run_v14.py train --seed 1 --out results/v14/n_seed1          # ~85 min (GPU)
PYTHONPATH=src:scripts python scripts/run_v14.py train --seed 0 --out results/v14/n_seed0
PYTHONPATH=src:scripts python scripts/run_v14.py train --seed 1 --level --out results/v14/n_level_seed1
PYTHONPATH=src:scripts python scripts/run_v14.py baselines                   # V8 seed 0 and 1 on the same features
PYTHONPATH=src:scripts python scripts/run_v14.py score                       # results/v14/val_table.md, a minute
PYTHONPATH=src python -m pytest
```

The level variant caches the dBFS levels in data/processed/v14_dbfs on its first run; the log-CQT caches
are V13's and V8's, unchanged. `score` needs V10's frame_score tables (`python scripts/run_v10.py cache`)
and V11 seed 1's posteriors on the rebuilt features (`python scripts/v13_eval.py`). Where librosa's numba
cache cannot be written, set `NUMBA_CACHE_DIR` to a folder of your own (e.g. `.tmp/<branch>/numba`,
ignored by git).

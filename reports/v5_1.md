# V5.1: does a no-chord (N) class help the CNN tracker?

**Answer: no, a null result.** V5.1 gives V5's network, prior and decoder a 25th state, N (no chord:
silence, count-ins, fade-outs), trained on RWC-P's N labels. On val it finds part of the N, but calls
about as many chord seconds N, and its mean WCSR is 76.57% against V5's 76.98%. A decoder ablation
of 63 settings on the saved network reaches 76.72% at best, still below V5. V5.1 therefore keeps V5
as the frozen system, and its test numbers are V5's: **GuitarSet 72.9%, RWC-P 79.0%** (no new test
run). The finding: the network is not sure enough about N to tell it from quiet chords. Holding N back
removes false N about three times faster than it loses real N, but most of the freed seconds are
still wrong as chords, so WCSR barely moves.

| Val, best p_self per row | RWC-P | N found / false N (RWC-P) | GuitarSet | mean |
|---|---:|---:|---:|---:|
| V5 (24 states, p_self 0.4) | 78.55 % | n/a | 75.41 % | **76.98 %** |
| V5.1 as planned (p_self 0.3) | 78.68 % | 43 / 109 s | 74.45 % | 76.57 % |
| V5.1, best decoder of the ablation (p_self 0.3) | 78.89 % | 16 / 32 s | 74.54 % | 76.72 % |
| V5.1, no prior division (p_self 0.2) | 78.47 % | 36 / 81 s | 72.68 % | 75.57 % |
| V5.1 network alone, most likely state per beat, no HMM | 78.14 % | | 71.86 % | 75.00 % |

## Question

V5 has no no-chord class: N frames are left out of training and are always decoded as some chord.
`evaluate.score` scores N references (majmin compares N with N), so those seconds are always wrong.
RWC-P val has 107.5 s of N, 2.2% of its annotated time, so a perfect N class could add up to about
2.2 points on RWC-P. GuitarSet has no N at all, so there an N class can only cost.

## Setup

Everything is V5 (`configs/v5.yaml`, tag `v5`) except the number of states:

- **Targets** (`data_v5_1`): the label "N" becomes class 24. X, chords with no third and frames
  outside the annotated span stay masked, as in V5. A pitch-shifted N stays N.
- **Network** (`model_v5_1`): V5's CNN with a 25th output, 4,609 more weights (150,409), trained
  from scratch with V5's settings and seed. Training: 166,326 frames, 2,904 of them N.
- **Prior** (`acoustic_hmm_v5_1.training_prior`): chords in all 12 keys as in V5; N is its share of
  the training frames, 1.75% (each major chord 5.54%, each minor 2.65%).
- **Change prior**: V3's 25 x 25 `change_matrix`, which V5 cut down to 24 x 24. Billboard has no N
  counts, so V3's rule fills N in: a chord moves to N with the weight of an average chord move
  (Q[chord, N] = 1/24 = 4.2%), and N moves to every chord equally.
- p_self swept on V5's grid (0.2 to 0.8). WCSR is reported with the N seconds found, missed and
  falsely called N (`acoustic_hmm_v5_1.n_seconds`, read on a 10 ms grid).

## How the evaluation avoids leakage

Same rule as V0 to V5: **test is scored, never inspected**, and V5.1 has no test run at all. The
network's weights see train only. Every number in this report, and the decoder ablation, uses val.
The 1.2% N-change rate tried in the ablation is counted on RWC-P train labels.

**Decoder ablation** (`scripts/v5_1_ablate_decoder.py`, saved network, no retraining). Two knobs,
3 x 3 values, each at the 7 p_self values (results/v5.1/ablations/decoder.json):

- q_in, the share of a chord's changes that go to N: 4.2% (V3's rule), 1.2% (counted on RWC-P
  train: 95 of 8,076 changes), 0.5%.
- n_prior, the prior the decoder divides N by: x1 (1.75%, as trained), x2, x4. A larger prior
  lifts N less; it is a tuning choice, not a better estimate of P(N).

| at p_self 0.3 | q_in 4.2 % | q_in 1.2 % | q_in 0.5 % |
|---|---:|---:|---:|
| n_prior x1 | 76.57 % (43 / 109 s) | 76.47 % (28 / 89 s) | 76.40 % (23 / 89 s) |
| n_prior x2 | 76.63 % (35 / 91 s) | 76.53 % (23 / 72 s) | 76.54 % (18 / 62 s) |
| n_prior x4 | 76.71 % (21 / 43 s) | 76.71 % (16 / 32 s) | **76.72 %** (16 / 32 s) |

Mean WCSR of the two val sets; in brackets RWC-P N found / false N seconds. GuitarSet's false N
falls from 12.4 s (x1, 4.2%) to 1.9 s (x4, 0.5%).

## Findings (all from val)

**1. Holding N back removes more false N than real N, but WCSR barely moves.** Raising the N prior
from x1 to x4 (best row: q_in 0.5%, p_self 0.3) cuts false N on RWC-P from 109 s to 32 s (-77 s)
and on GuitarSet from 12 s to 2 s, while N found falls from 43 s to 16 s (-27 s): about 3 s of
false N removed per second of real N lost. Yet RWC-P WCSR rises only 0.21 points, about 10 s of the
~4,950 s scored. So of the 77 s no longer called N, only about 37 s become the right chord (27 s
make up for the lost N, 10 s are the net gain); the other ~40 s are decoded as a wrong chord. These
are quiet, sparse or ambiguous passages that neither N nor a chord fits well, and the network's N
posterior does not separate them from true N.

**2. The N transition rate hardly matters.** Once the prior is at x4, the three q_in values give
76.71 to 76.72%. V3's 1/24 rule overstates N moves 3.5 times (RWC-P train: 1.2%), but correcting it
changes little.

**3. The GuitarSet drop is the network's, not the decoder's.** Even with under 2 s of false N,
GuitarSet stays 0.9 below V5 (74.5 vs 75.4%), and the network's best-epoch frame accuracy there is
70.2% against V5's 71.6%. With one training run each, part of this can be run-to-run noise (MPS is
not bit-exact); it was not measured.

**4. The prior division and the HMM still matter.** Without the division the mean drops to 75.57%;
the network alone, with no HMM, gives 75.00%. The HMM adds 1.6 points, mostly on GuitarSet.

**5. Part of the reference N cannot be heard.** All 20 RWC-P val songs (and all 60 train songs)
have annotations that end about 2 s after their audio file. 32.7 of val's 107.5 s of N lies there,
where the decoder has only the last frame to go on. The same seconds are scored for every version,
so the comparison with V5 is fair, but the reachable N gain is about 1.5 points, not 2.2. The same
tail is why training saw 2,904 N frames rather than the ~4,080 that 379 s of N would give.

## Limitations

- One training run per system; run-to-run noise was not measured.
- Only ~2,900 N training frames (1.75%), all from RWC-P.
- 63 decoder settings were tried on the same val songs, so the best one is slightly optimistic;
  it still does not reach V5.

## What the next version should look at

- **V5.2: regularization and more data (AAM).** AAM labels its silences N.C., so it brings many more
  N examples; the N class can be retried on top of V5.2 rather than V5.
- **The annotation tail.** Trimming references to the audio length (or reporting it separately)
  would make N scores reflect what can be heard; it would change every version's numbers slightly,
  so it belongs in a protocol note, not in one version.
